## Phase Goal

**As a** AI Agent developer using crud-cli, **I want to** run `crud-cli validate` to catch template errors (syntax / unknown variables / render failures / missing helpers) BEFORE invoking `gen`, **so that** I never waste tokens debugging templates inside a generation run and I get a single aggregated error report I can fix in one pass.

This is the final vertical slice of Phase 2: a working `validate` command that completes VAL-01..04. Builds on Plan 01 (template_loader, template_engine, gen_context, ErrorEnvelope) and Plan 02 (setup.toml `[variables]` flowing into the synthetic fixture).

<objective>
Implement `validate` per D-G20, D-G22, D-G23 and VAL-01..04:

1. **Discover templates** via the same `template_loader::discover_templates` used by `gen` (project-only `.crud/templates/`, `.crudignore` respected, optional `--type` filter for parity).
2. **Per template, run three checks (fail-fast within ONE template, aggregate ACROSS templates):**
   a. Syntax: `handlebars::Template::compile(&body)` — captures unclosed blocks, malformed `{{` tokens, etc. → `kind=syntax_error` issue.
   b. Variable first-segment check (D-G22): walk the compiled `Template` AST, collect `Expression::path` first segments, intersect with the allowed set `{ built-in keys, [variables] keys, each-loop locals: field/@index/@key/@first/@last }`. Each disallowed first segment → `kind=unknown_variable` issue with `strsim::levenshtein ≤ 2` suggestion.
   c. Render with synthetic fixture (VAL-03): hardcoded 3-field `GenInput` (id PK + email non-null + status with default — choice within D-G20 discretion), merged with `setup.variables`, run through `gen_context::build_context` then `template_engine::render_template(&body, &fixture_ctx)`. Any error → `kind=render_error` issue. Any unrendered `{{` substring remaining → `kind=render_error` issue with `variable=<extracted-handle>`. Errors mentioning unknown helpers → `kind=missing_helper`.
3. **Aggregate** all issues across all templates per D-G23. On success (zero issues) return `Ok(ValidateReport { templates_checked, issues: 0 })`; on any issues return `Err(ErrorEnvelope { kind=TemplateError, exit_code=2, details: { summary: { templates_checked, templates_with_issues, issue_count }, issues: [{template_path, line, column, kind, variable, suggestion}, ...] } })` matching the exact field names from VAL-04.
4. **CLI surface:** add `ValidateArgs { type_: Option<String> }` (mirror gen for parity), `Commands::Validate(ValidateArgs)` variant, `run_validate` dispatcher in `src/cli/commands/validate.rs`, wired through `src/main.rs`.
5. **Contract test:** `tests/contracts/validate_agent_stdout.rs` — success path emits `validate ok: N templates` (silent under `--agent` per emit_success semantics); failure path empty stdout, structured JSON envelope on stderr with `kind=TemplateError`, `exit_code=2`.

Purpose: ship VAL-01..04 fully, satisfy Phase 2 SC#3 (the validate success criterion in ROADMAP).

Output: `crud-cli validate` works against the seed-project templates with the right exit codes and structured stderr.
</objective>
