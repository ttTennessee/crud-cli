## Phase Goal

**As a** AI Agent developer using crud-cli, **I want to** drive `crud-cli gen` via `--file user.json` (or rich `--fields`), have front-matter and `setup.toml` mappings control output paths, filter renders by `--type`, and preview with `--dry-run`, **so that** real RuoYi-style template sets (Java backend + Vue frontend split across many files) generate correctly with byte-identical results regardless of input mode.

This plan extends the vertical slice from Plan 01: same pipeline, more branches. JSON input, front-matter, output-mapping, `--type` filter, `--dry-run` UX, and `[variables]` merge replace the Wave-1 stubs. Plus the atomic-batch contract test that locks Phase 2 SC#5.

<objective>
Complete the `gen` user-visible surface for Phase 2:

1. **JSON input (GEN-02, D-G13..G19):** `gen --file user.json` reads a hybrid-schema entity, applies CLI overrides for `name`/`package`/`table`, uses `serde_path_to_error` for precise error paths, did-you-mean (`strsim`) for `unknown_field`. Errors are `UserError(1)`, NOT `ConfigError(5)`.
2. **Front-matter (GEN-06, D-G28 layer 1, D-G29, D-G30):** parse YAML `---` front-matter with `gray_matter`; render `basePath`/`filename` through Handlebars; reject `filename` containing `/` and any output path with `..` or absolute components.
3. **Output mapping (D-G27, D-G28 layer 2):** read `[templates.outputs]` from `setup.toml` (keyed on template rel_path); render mapped value through Handlebars; fall back to source-mirror (Plan 01 behavior) when no entry.
4. **`--type` filter (D-G31, D-G32):** comma-split prefix match against template `rel_path`; missing types → `UserError(1) reason=template_type_not_found` with hint listing available types (scan `.crud/templates/` top + 1 nested level).
5. **`--dry-run` UX (GEN-08, D-G30):** emit a stable human-readable listing (one `<resolved-path>  (N lines)` per line, with `[CONFLICT]` marker for existing paths under `Never` policy) — goes to stdout in non-agent mode, stays silent under `--agent` (consistent with Phase 1 `emit_success` semantics — listing under agent mode goes to stderr at INFO level).
6. **`setup.toml` extensions (D-G21):** `[variables]` table (free-form TOML, blacklist enforced at load) + `[templates.outputs]` table. `[variables]` values flow into Handlebars context (top-level merge, blacklist re-checked).
7. **Atomic-batch contract test (Phase 2 SC#5):** new `tests/contracts/gen_atomic_batch.rs` proving the batch-fail-zero-writes invariant.
8. **`--agent` contract test for `gen`:** new `tests/contracts/gen_agent_stdout.rs` mirroring `tests/contracts/agent_output_contract.rs` shape, asserting success-line discipline + failure-silence.

Purpose: ship the full Phase 2 `gen` UX (modulo `validate`, which is Plan 03) and lock the contracts.
Output: every Phase 2 success criterion #1, #2, #4, #5 demonstrably true.
</objective>
