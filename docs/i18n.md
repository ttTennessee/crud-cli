# Internationalization (i18n) Conventions

This document is the source of truth for user-facing language in `crud-cli`.
All new features MUST follow it.

## Scope

i18n covers **interactive prompts**, **error message hints**, and
**human-facing success lines**.

It does NOT cover:

- **`clap --help` / `--version` text** — intentionally kept English.
- **Error envelope `msg`** — kept as stable English (machine-leaning) text.
- **Error envelope `reason`** — a closed-set, snake_case English machine key;
  it is part of the agent contract and never translated.
- **TOML keys, enum identifiers, file paths, flag names** — never translated.

## Languages

Two locales are supported today: `en` (default) and `zh`. Catalogs live in:

- `src/core/i18n/en.toml`
- `src/core/i18n/zh.toml`

## Locale resolution

| Context | Active locale |
|---------|---------------|
| Agent mode (`--agent` / `CRUD_AGENT=1`) | always `en` (deterministic JSON) |
| `CRUD_LANG` env var set | that value (highest non-agent priority) |
| `~/.crud/config.toml` → `[ui] lang` | the stored preference |
| none of the above | `en` (default) |

The process locale is applied once at startup by `cli::init_locale()`.

### First-run preference

When the **interactive** `setup` / `setup --project` wizard is about to run and
no preference exists (no `CRUD_LANG`, no stored `[ui] lang`), the user is
prompted to choose a language. The choice is persisted to
`~/.crud/config.toml`. Non-interactive (flag-driven) and agent runs never
prompt.

## Key naming convention

Format: `<domain>.<subject>.<detail>`

- All lowercase, `snake_case` segments, dot-separated.
- `<domain>` is the feature area: `setup`, `wizard`, `gen`, `validate`,
  `template`, `error`, ...
  - `wizard.template.*` covers the project wizard's "installed templates"
    branch and the manual language picker.
  - `template.*` covers the `crud-cli template use|list` subcommand.
- For errors, prefer `error.<area>.<reason>` (e.g. `error.field.empty_type`).
- Leaf keys hold strings only; never make a key both a string and a table
  (e.g. use `wizard.cancelled_msg` + `wizard.cancelled_hint`, not
  `wizard.cancelled` + `wizard.cancelled.hint`).

Placeholders use named braces, e.g. `{path}`, `{count}`, `{bundle}`.

### Examples

```
setup.created                 = "Created {path}"
wizard.help.backend           = "Project backend stack (D-08)"
gen.success.written           = "Generated {count} files"
error.field.empty_type        = "field needs a type: write name:Type ..."
error.type_map.unmapped_bundle = "add {type} to the [map] in .crud/templates/{bundle}/..."
```

## Adding a new string

1. Add a `&'static str` constant to `src/core/i18n/keys.rs` and append it to
   `ALL_KEYS`.
2. Add the matching entry to **both** `en.toml` and `zh.toml`.
3. Use it in code:
   - `i18n::t(keys::MY_KEY)` for static text (returns `&'static str`).
   - `i18n::tf(keys::MY_KEY, &[("name", value)])` for interpolation.
4. The unit tests in `src/core/i18n/mod.rs` enforce that every `ALL_KEYS`
   entry exists in both locales and that the two catalogs have identical key
   sets — they will fail if you forget a translation.

## Testing tips

Pin the locale in tests that assert on human output, so results do not depend
on the developer's `~/.crud/config.toml`:

```rust
Command::new(exe()).env("CRUD_LANG", "en") /* ... */
```
